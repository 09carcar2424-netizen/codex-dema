## 현재 중요한 원칙

- 고객 공개 기능보다 내부 운영 MVP를 먼저 완성한다.
- 고객 도메인은 고객 명의, 고객 애드센스도 고객 명의로 운영한다.
- BOSS는 기술대행, 콘텐츠 운영대행, 검수/운영관리 역할로 간다.
- 수익 보장, 애드센스 승인 보장, 도메인 안전 보장 표현은 금지한다.
- IP, 서버, VPN은 보안/격리/운영 안정성 목적으로만 설명한다.
- 정책 우회, 추적 회피, 은폐처럼 보이는 표현은 사용하지 않는다.
- 자동화보다 수동 검수와 감사 로그를 우선한다.

## WordFriends 장기 방향

WordFriends는 단순 고객 포털이 아니라 장기적으로 검수 기반 도메인/사이트 운영자산 플랫폼으로 확장할 수 있다.

초기에는 고객 공개 거래 기능을 만들지 않는다. 내부 MVP에만 아래 개념을 뼈대로 준비한다.

- BOSS 보유 도메인 재고
- 고객 보유 도메인
- 신규 추천 도메인
- 도메인 검수 리포트
- 운영 이력
- 색인 상태
- 애드센스 상태
- 판매/중개 가능 여부
- 리스크 메모

향후 고객 요청이 많아지면 WordFriends에서 도메인 또는 운영 사이트 중개 플랫폼 형태로 확장할 수 있다. 이때도 BOSS는 수익 보증자가 아니라 검수 자료 제공자, 세팅/운영 대행자, 거래 중개자, 운영 이력 관리자 역할로 제한하는 것이 안전하다.

## 영어 사이트 우선 전략

앞으로는 가능하면 영어 홈페이지 제작을 우선한다.

- `.com`, `.net`, `.org` 중심
- 신규 도메인 또는 검수된 에이징 도메인 확보
- 카테고리와 자연스럽게 맞는 브랜드성 도메인 우선
- 상표권, 스팸, 과거 이력, 백링크 품질, 색인 상태를 검수
- 고위험 YMYL 주제는 수동 검수 강화

초기 권장 카테고리:

- Home improvement
- Cleaning
- Outdoor living
- Pet care
- Hobbies
- DIY
- Education tips
- Travel information
- Productivity
- Sustainable living
- Tech explainer

건강/의료성 콘텐츠는 가능하지만 YMYL 리스크가 높으므로 진단, 치료, 효능 보장 표현을 피하고 면책/출처/검수 체계를 강화해야 한다.

## PC와 Ubuntu 작업 방식

앞으로는 긴 채팅을 복사해서 주고받는 방식보다 아래 흐름을 권장한다.

1. PC Codex에서 기능 개발과 화면 확인
2. GitHub에 commit/push
3. Ubuntu 서버에서 `git pull`
4. 필요 시 DB import/build/API restart
5. 장기적으로 `npm run deploy` 같은 자동 배포 명령으로 단순화

Ubuntu에서 자주 사용할 명령:

```bash
cd /home/boss/codex-dema
git pull
npm run build
```
